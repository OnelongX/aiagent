## I. 一个反直觉的核心论点

写过 13 篇 Agent 实战之后,有个反直觉的结论必须先说清楚:

**AI Agent 落地的真正门槛,不是技术,是认知。**

90% 的人卡在这三件事:

1. 以为 Agent = 一个超大 Prompt(实际上是工具调度器)
2. 以为模型越大越好(实际上要按任务分)
3. 以为先有评测再做产品(实际上是先做 MVP 后补)

技术上,**Claude Agent SDK + LiteLLM 是 2 小时能上手的东西**。难的是:

- **看见自己行业 20 年的 Excel 是 6 个工具**
- **看见自己客户的对话流程是 4 个 Subagent**
- **看见自己的红线规则是 5 个 Hooks**

这才是 Agent 时代真正稀缺的能力。

## II. 13 篇沉淀的 1 个框架

不管行业怎么变,Agent 工程的骨架就 4 层:

```
┌─ 渠道层      微信 / 网页 / 邮件 / 企微 / API
├─ 状态层      Redis (session) + Postgres (history)
├─ Agent 层    主 Agent + N 个 Subagent (分工)
└─ 工具层      信息 (读) + 动作 (写) + 分析 (评)
```

13 篇都是这个骨架。**换行业只换数据 + 工具,骨架照搬**。

## IV. 任务 × 模型矩阵 —— 找对模型

"用 Claude 还是 GPT-5 还是 Gemini" 是错的问法。
**正确问法**:这个任务用哪个模型?

| 任务类型 | 首选 | 次选 | 不用 LLM |
|---|---|---|---|
| 长链推理 / 合规语言 / 共情 | **Claude Sonnet 4.5** | Opus(更深) | – |
| 结构化提取 / 严格 JSON | **GPT-5** | GPT-5 mini | – |
| 多模态(图像 / PDF / 表格) | **Gemini 2.5 Pro** | Claude 多模态 | – |
| 长上下文(2M token) | **Gemini 2.5 Pro** | – | – |
| 意图分类 / 路由 | **Haiku** | GPT-5 mini | – |
| 风控 / 多变量评分 | **GPT-5** | Opus | – |
| 价格 / 数字密集 | **GPT-5** | – | 走数据库 |
| 召回 / 向量检索 | – | – | **Qdrant + BGE-M3** |
| 重排 | – | – | **Cohere rerank-3.5** |
| 规则匹配 | – | – | **正则 + 规则引擎** |

**一个项目里 3-4 个模型并存是正常的**。LiteLLM 一层封装,task_type 决定调谁。锁单一供应商 = 锁短板。

## V. 5 个行业无关的工程定律

13 篇沉淀的规律,**任何行业都成立**:

### 定律 1:工具优先 · LLM 不计算

任何数字 / 价格 / 状态 / 时间,**全部走工具**。LLM 算 8 × 1500 都可能错,不要让它算复利、阶梯电价、库存。

### 定律 2:权限在数据层 · 不在 Prompt

错:"你是 HR,只能回答 HR 问题"(prompt injection 一句话就突破)
对:在向量库 filter,LLM 接触不到不该看的 chunk。**LLM 不能负责安全**。

### 定律 3:Subagent 分工 · 一个 Agent 别干太多

主 Agent 调度,Subagent 各管一段。triager 用 Haiku 分流,info/action 用 Sonnet。**单次对话成本可压 1/5**。

### 定律 4:Hooks 守红线 · 不让 LLM 决定边界

价格 / 金额 / 承诺 / 状态机 / ACL —— 这些**绝对不能让 Claude 自由发挥**。Hook 写死规则,Claude 在规则内自由。

### 定律 5:评测驱动 · 没评测就没生产

- RAG 场景 → RAGAS 4 指标(Faithfulness / Relevancy / Precision / Recall)
- 客服场景 → CSAT / Containment / AHT / FCR
- 自媒体 → 阅读量 P30 / DSAT 闭环

**任一指标跌 5% → block 上线**。

## VI. 6 个跨行业 case 速览(灵感库)

### Case 1:律所合同审查助手

模板:[合同审查助手](内部链接)
变量:把"绿电方案库"换成"红线条款库",把"组件 SKU"换成"判例 ID"。多模型交叉验证压漏判到 <2%。
工程量:**3 周 MVP / 3 个月调优**。

### Case 2:医院影像分诊台

变量:Gemini 接 DICOM 影像 + 病历摘要 + 既往史。Claude 出分诊建议,**所有结论必须标"不替代医生"**。
工程量:**4 周 MVP / 6 个月合规审批**。

### Case 3:银行 KYC + 投顾

变量:GPT-5 跑结构化评分(年龄 / 收入 / 风险偏好 / 历史交易),Claude 出报告。**绝不允许 Agent 推荐具体证券**(合规红线)。
工程量:**4 周 + 牌照流程**。

### Case 4:K12 个性化辅导

变量:Gemini 批改作业图,Claude 出错题分析,GPT-5 跑题目难度匹配。**家长侧用 Haiku 跑日报**(便宜)。
工程量:**3 周 MVP / 1 学期数据闭环**。

### Case 5:工厂 MES 助手

变量:Claude 接 MES 数据(产线 / 设备 / 不良率)+ SPC 图。问"为啥今天良率掉了?" → 多变量归因。
工程量:**2 周(数据已有的话)**。

### Case 6:12345 政务热线

变量:KB 接政策库,Claude 答询,**任何"承诺办结时间"必须 hook 拦截改写**(合规)。转人工带摘要。
工程量:**4 周 + 等保过审**。

**模式一样,数据不同**。

## VII. 起步路径 —— 技术门槛不高的具体证明

不需要算法团队,不需要训练模型,不需要超算。**普通工程师从零起步到第一个 MVP**:

| 阶段 | 时间 | 你需要做 |
|---|---|---|
| 装环境 | 30 分钟 | `pip install claude-agent-sdk litellm` |
| 拿 API key | 10 分钟 | 注册中转服务 / 官方 console |
| Hello World | 30 分钟 | 跑通官方 query 例子 |
| 加 1 个自定义工具 | 1 小时 | 包一个 Python 函数 |
| 加 Subagent + Hook | 半天 | 照 docs 抄 |
| 接自己数据库 | 1-2 天 | SQLAlchemy + REST |
| 接微信 / 飞书 / 邮箱 | 2-3 天 | webhook + 现成 SDK |
| **完整 MVP 上线** | **3 周** | 行业落地 5 篇任何一篇都给了完整代码 |

**所有工具都是普通 Python 函数**。数据是公司本来就有的。模型走 API,不用自己部署。

**唯一稀缺的是产品理解** —— 你得知道你的行业 20 年来的 Excel 是哪 6 个工具。

## VIII. 5 个常见误区

### 误区 1:Agent = 一个超大 Prompt

错。Agent = **调度器 + 工具集 + 规则集**。Prompt 越大越发散,工具越多越精准。

### 误区 2:模型越大越好

错。triager 用 Haiku(便宜),主推理用 Sonnet,深思考偶尔用 Opus,JSON 提取走 GPT-5。**一个项目混搭 3-4 个模型是常态**。

### 误区 3:评测可以后补

错。没有黄金集 / RAGAS / CSAT 闭环,第二周就开始飘。**评测从 day 1 起步**。

### 误区 4:越自动越好

错。Containment Rate(AI 独立解决率)**控制在 60-80% 最优**。太高反而漏失高价值客户。**转人工兜底比自动重要**。

### 误区 5:风格 / 调性调不准

错。Few-shot + Embedding 校验 + Persona Lock 三层叠加,**比 fine-tune 还稳**。

## IX. 真正打开思维的 3 个问题

不要问"怎么做 Agent",要问:

1. **我这个行业的 20 年 Excel,能拆成多少个确定性函数?**
2. **我的客户在我这儿做的事,能拆成多少段流水线?**
3. **我们的红线规则(合规 / 风控 / 金额 / 承诺),哪些必须写成 Hook?**

回答完这 3 个问题,**Agent 的骨架就已经画出来了**。

剩下的是套模板。

## X. 升华

### 不是 "AI 取代专家"

是 "把专家的工具栈,让普通人也能调"。

- 设计院 3 万的光伏方案 → Agent 5 分钟出
- 律师 5000 一份的合同审查 → Agent 10 分钟标记 + 修订
- 客服 3 天才回的工单 → Agent 当场答 + 转人工带摘要
- 自媒体 6 小时的一篇文 → Agent 30 分钟出 + 一稿多发

**专业知识不再是稀缺品。专业知识的可调用性,才是稀缺品。**

### 写在最后

13 篇下来,从工具栈到行业落地到跨行业平移,跑通的核心结论就 1 句:

**Claude Agent SDK 的工程模式是行业无关的。**

绿电、合同、知识库、客服、电商、二手 3C、自媒体 —— 7 个完全不同的领域,**同一套骨架都撑得住**。

接下来法律 / 医疗 / 金融 / 教育 / 制造 / 物流 / 农业 / 房地产 / 政务 / HR / 营销,只是换数据 + 换工具,**骨架不动**。

**真正的门槛**:你愿不愿意花 1 周时间,把自己行业的隐性知识,变成 20 个工具 + 4 个 Subagent + 5 个 Hooks。

愿意的,2026 年是 Agent 红利的最后窗口。

不愿意的,继续看别人享受复利。
